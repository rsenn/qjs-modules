#path: qjsm against Node, Bun and Deno (2026-10-17)

quickjs-path.c (qjsm path) compared with node:path in node 22.23.3, bun 1.4.2 and deno 2.9.7. Supersedes section "quickjs-path.c gaps" of api-compatibility-nodejs.md where they disagree.

Plan to close the gaps: api-interface-path.md (Node/Bun/Deno compatibility) and api-implement-path.md (C migration); steps in TODO.md Tier 22.

Reproduce:

./dump-node-path.sh                                               # all four runtimes, /tmp/node-path-surface
utilities/describe.sh -r qjsm --flat --no-arguments path          # one runtime
utilities/describe.sh -r node --flat --no-arguments node:path     # likewise bun, deno
~/.claude/skills/quickjs-scripting/scripts/portable-check.sh battery.mjs   # behaviour

Deno needs describe.sh run without the 4 GB ulimit -v (it aborts on startup under it).

#1. Node, Bun and Deno agree with each other

The three export the same 17 names, and a 234-line battery (every function on 24 paths, join/relative/resolve/format on edge inputs, argument validation) printed identical output on all three. Node is therefore the reference.

#3. Behaviour

Of the 234 battery lines, qjsm differs from Node in 27. All of them are argument validation, none is a wrong result for a valid path:

callqjsmNode, Bun, Deno
basename, dirname, extname, isAbsolute, parse, join (also join('a', null), basename('a', 3)) with a non-stringfixed 2026-10-17 (steps C1-C3): TypeError, code ERR_INVALID_ARG_TYPE, Node's message word for wordsame
typeof path.win32undefinedobject

normalize, relative, resolve and format throw Node's error too (steps C4, 2026-10-17: from, to, paths[i], pathObject). One difference remains (relative(x) throws for the missing to like Node since 2026-10-22): format({ base: 5 }) returns "5" where Node returns the number 5. The valid-input half is pinned by tests/unittests/test-path-node.js (@portable, table generated by utilities/gen-path-golden.mjs), the parts that already agree by tests/unittests/test-path-interface.js.

#4. Findings

  1. The valid-input behaviour of the 13 shared names matches Node, Bun and Deno on every case of the battery, so the old "wrong results" warning no longer holds.
  2. Argument validation: all ten functions now throw like Node (C1-C4); Function.length matches too (C5).
  3. Absent: win32, matchesGlob, toNamespacedPath, path/posix, path/win32.
  4. qjsm exported 38 names none of the three has; 25 were removed 2026-10-22. The rest (exists, isDirectory, isFile, isSymlink, realpath, getcwd, gethome, fnmatch and its constants, skip) have users.
  5. exists agrees with fs.existsSync on dangling symlinks since 2026-10-22 (C9).
