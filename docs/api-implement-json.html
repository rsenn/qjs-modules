#JSON: how the implementation is split

> Status 2026-10-18 (implemented). The event model is in: every class is a source or sink over JsonEvent / XmlEvent, pump()/connect()/tee/JsonBuilder/XmlBuilder exist, parse() and XMLNodeParser are removed (next() and the iterator replace them), xml.write() is xwalk pumped into an XmlWriter (XW_PRETTY, indent 2), quickjs-json.c is 933 and quickjs-xml.c 967 lines (2026-10-18: json.c is gone, JsonParser is a queue over jread; the push parser, the serializer and the pump moved into src/json/). The layering described below is done except the lib/ glue for read/write, which stay native. > Running state and what is left: event-model-state.md. Text below that describes parse(), XMLNodeParser, > eventName/eventValue, PARSE_*, xtreewrite or xlayout is the plan or the history, those are gone.

quickjs-json.c should be a binding layer: classes, argument parsing, error mapping. The parsing, walking, building and writing live in include/ + src/ pieces that know nothing of JS classes, and most of them nothing of the engine. This document records where the code is now, what each shared header could still take over, and what is left in the binding. Companions: api-compare-json.md (against other runtimes), api-interface-json.md (the interfaces between the pieces), TODO.md Tier 18.

State 2026-10-17: quickjs-json.c is 1809 lines, src/ pieces 3106 (jread 794, json 653, jwrite 527, walk 531, jwalk 368, jbuilder 233). 71 tests in test-json.js; write() equals JSON.stringify on 420 cases through both write and JsonSerializer.

#3.1 read() off sj.h

read() is the one duplicate of JSON.parse and the least correct (api-compare-json.md 3). Replace its body by jread strict + jbuilder with ordinary prototypes, or drop it for JSON.parse after the deprecation (Tier 18 step 5). Either way ParseFrame, parse_val, parse_primitive, parse_make_container, parse_throw, js_json_parse (about 185 lines) and the vendored sj go. Interim fix: decode escapes (BUGS).

#3.2 JSONL scanner

jsonl_is_ws and jsonl_value_end (45 lines) are pure C. Move them to jread as jr_value_end(buf, n, i) or to a jsonl.c beside it; the per-value JS_ParseJSON stays (it is exactly Bun's semantics, and recursion depth per line is bounded by the line). With 3 above, JSONL shrinks from 195 to about 90 lines.

#3.3 Options

JsonWriteOptions already carries indent, indent_str, bare_keys, single_quotes, hex_numbers, minify. JSON5.stringify needs no new engine code, only the binding to set them; jwrite_options_indent* lets the constructor of JsonWriter and JSON5.stringify share the space rule with write().

#5.2 Throwing

One helper for every parser binding, in quickjs-location.[ch] (the module that owns Location):

/* builds a SyntaxError with own, non-enumerable loc (a Location clone), length and code.
 *
 *   const Location*  at      start of the offending token
 *   size_t           length  characters it spans (0 at end of input)
 *   const char*      code    stable kebab-case name
 *
 *   returns JSValue  the error object (refcount: a new reference), or JS_EXCEPTION */
JSValue js_syntax_error_new(JSContext*, const Location* at, size_t length, const char* code, const char* fmt, ...);
/* ... and throws it: returns JS_EXCEPTION with the SyntaxError pending. */
JSValue js_throw_syntax_error(JSContext*, const Location* at, size_t length, const char* code, const char* fmt, ...);

The object form is needed where nothing is thrown: JSONL.parseChunk().error, onError(err) / onParseError(err), parser.error, the members of an AggregateError, a promise rejection. The message is "<text> at <file>:<line>:<column>".

#5.4 Tests

tests/unittests/test-json-errors.js, table driven: for every parser (read, JsonParser, JsonPushParser, JSONL, Blob.json, JSON5/JSONC.parse) and every input class (bad token, EOF inside a string, bad escape, trailing data, trailing comma, comment in strict mode, CRLF and lone-CR line breaks, an astral character before the error): class, code, loc.line/column/charOffset/byteOffset, length. Two properties on top: chunk invariance (the push parser fed 1 byte at a time reports the same loc and code as fed whole) and differential loc against json5 (lineNumber, columnNumber) on 200 generated bad inputs.

Size: srcpos.h about 60 lines, js_syntax_error_new about 50, per-parser changes about 15 lines each; the throw sites shrink.

#6. State 2026-10-17

Done: layout move; jwalk over a generic walk (circularity check O(1)); JsonEventSink, jwrite_sink/jbuild_sink, pumps; js_jsonsink_* (src/json/jsink.c, no user yet); JsonPushParser on the sink; error contract E0 to E2; quickjs-json.c is 1962 lines. Sections 2 to 4 above predate this; the open items are in TODO.md, "Remaining work: json and xml" (J1 to J7, B1 to B9).

#7. Plan 2026-10-18: engines in C, APIs in lib/

Decision (api-event-model.md): quickjs-json.c stops carrying dialect and runtime APIs. It holds engines, each a source or a sink, pull or push, over JsonEvent; JSONL, JSON5, JSONC, read, write and the @std/json streams are compositions in lib/. What that does to the pieces:

PieceNowAfter
json.c (pull)json_parse(p) returns an event type or JSON_NEED_DATA / JSON_NONE / JSON_ERROR, text in json->tokenJsonPull json_next(p, &ev): fills a JsonEvent (type, text, start SourcePos); an error is an event
jread.c (push)jr_callback(type, jr_str_t*, user)JsonEventHandler(user, const JsonEvent*); jr_read returns the first negative handler result
jpump.cjread_pump, jread_pump_finish, json_pump with a private callbackjevent_pump(json_source(parser), sink), the 3-line loop; the push pumps are one call of jr_read with jevent_send as handler
jwalk.cdrives a WalkInterfacealso jwalk_event(&src, &ev), a pull source (capturing WalkInterface inside the iterator)
jbuilder.cjbuild_*, jbuild_sinkadds the proto option, the completed-roots queue with end positions, jbuild_value_js()
jwrite.cJsonWriter, jwrite_sinkunchanged; gets comment and raw sink members
jsink.cC sink to JS objectadds the other direction (JS object to C sink) and the handshake Symbol.for('qjs.jsonsink')
serializer (in quickjs-json.c)JsonSerializer over a valueone struct: pull source + JsonWriter + DynBuf + demand; the source may be a walker or a JsonParser

Lines expected to leave quickjs-json.c (the target of section 6 of TODO.md, about 1620, drops to about 1300): the JSONL functions, read, write and their option parsing (P9), the private token numbering of JsonParser (P2), the callback glue of JsonPushParser (P3). Rules for every step: test-json.js stays green apart from the changes listed in TODO.md; output is the same at every chunk size; the JSON.parse / JSON.stringify differential stays at 0.

#7.1 End state (plan 2026-10-18)

After the binding is lifted quickjs-json.c is the list of classes (about 900 lines): JsonParser, JsonPushParser, JsonBuilder, JsonWalker, JsonWriter, JsonSerializer, tee. The rest goes to src/json/: error shaping (js_syntax_error_from_event, about 220 lines of the binding), option parsing and the space rules (jopts.c), event to JS value and JS-function handlers (jevent-js.c), handshake and js_json_pump (jconnect.c), the serializer's read() (jserial-js.c). Deleted: the vendored reader (lines 29 to 290), JSONL.* and write() (to lib/), the walk glue of JsonWriter (lines 1446 to 1535), the old entry points of json.h / jread.h (private), and one of the two tokenizers (jread.c 1546 lines, json.c 1148 lines) after the measurement of api-event-model.md 12.3. Details, counts and gates: api-event-model.md 12; state: event-model-state.md.
