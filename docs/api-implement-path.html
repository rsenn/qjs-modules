#Plan: path_* C functions onto the shish names (2026-10-17)

Status: R1-R12 done. src/path.c is deleted; src/path-sys.c holds the non-lexical functions; the JS-only helpers are static js_path_* in quickjs-path.c.

Goal: quickjs-path.c and every other C client call path_* functions whose names do not end in a digit, and the names common with ~/Sources/shish/lib/path.h mean the same thing in both projects. src/path.c goes away. The exact task list is in TODO.md, Tier 22 (steps R1-R12; the Node-compat steps T, C, W, G of api-interface-path.md are in the same list, ordered so a rename and a behaviour change never share a commit).

#1. Where things stood (before R1; the work is done, see the status line above)

  • src/path-lib.c (398 lines) already implements part of shish's path.h: path_rootlen, path_basename, path_dirlen, path_cat, path_canon, path_abs, path_common, path_rel, path_extoff, path_listlen, path_listnext, path_search.
  • src/path.c (650 lines) holds the old digit-suffixed API (path_exists1, path_at4, ...), include/path.h declares both generations plus 14 static inline helpers and macros.
  • The digit is the argument count, an old naming style (path_length1(p), path_length2(p, n)). shish's rule is (pointer, length) always, caller's buffer out, no digit.
  • No sibling qjs-* project and no .js file uses any of the digit-suffixed functions; all clients are inside this repo (section 3).

The _s convention (shish: path_basename_s(s) is path_basename(s, str_len(s), 0)) also covers the NUL-terminated callers of the new src/path-sys.c functions: path_exists_s, path_isfile_s, path_issymlink_s are macros over path_exists(p, n) and the like.

#4. Order of work

The authoritative, numbered list is TODO.md Tier 22 (R1-R12 here, plus T/C/W/G of api-interface-path.md). What follows is the reasoning behind its order.

  1. Audit and tests first: usage audit of the JS methods; a differential test for path_fnmatch (old against shish's) and for path_realpath3 against path_resolve.
  2. Port the missing shish functions into src/path-lib.c and declare them.
  3. Create src/path-sys.c with the 3.1/3.2 functions; each old function becomes a one-line wrapper in the same commit only if a client still needs it, otherwise it is removed at once.
  4. Migrate clients, one file per commit: src/compat/glob.c, quickjs-misc.c, src/child-process.c, src/qjsm.c, then quickjs-path.c.
  5. Move or delete the 3.3 helpers.
  6. Delete src/path.c, the digit-suffixed declarations and the static inline helpers from include/path.h; check the CMake source list (the sources are listed by glob, verify the deleted file does not leave a stale entry).

Verification after every step: tests/unittests/test-path.js (42 tests), test-glob* and the qjsm tests under ctest; at the end utilities/api-surface.sh on the path module before and after (diff must be empty apart from the deleted JS methods), and rg 'path_[a-z]*[0-9]\(' returns nothing.

#5. Risks (all handled by R1-R12; checked 2026-10-17)

  • Arity clash: path_isabs/path_isname exist today as 1-argument macros; shish's are 2-argument functions. A half-done migration compiles into calls that silently use the macro. Step R1 renames the macros (_s) before step R2 introduces the functions, so the two never coexist under one name.
  • PATH_FNM_NOMATCH and PATH_FNM_PATHNAME are both 1 in include/path.h and in shish's header (fnmatch(3) has FNM_NOMATCH as a return value, not a flag); keep, but never use PATH_FNM_NOMATCH as a flag.
  • path_gethome changes meaning ($HOME, no argument, to /etc/passwd, by uid); the only client is src/compat/glob.c, which must keep ~ working from $HOME.
  • Windows: path_isabs follows shish (C:x relative), and path_issymlink keeps the is_symlink branch; none of it can be run here, so the Windows branches are reviewed, not tested.
  • path_realpath3 fails on a missing file, path_resolve does not; the JS realpath keeps its current behaviour only if the existence check stays in quickjs-path.c.
