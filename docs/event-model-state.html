#Event model v2: state of the refactor

Living status of the work specified in api-event-model.md (design, sections 1 to 10; end state, section 12). The backlog and gates are in TODO.md, "Event model v2". This file records what is done and how it was checked, file by file, so a later session can continue without re-deriving it. Update it in the same change as the code.

Last update: 2026-10-18. P1 to P8 (include/ and src/) are committed as 21a5513f; P11 is in the working tree.

#3.3 P11: error code and span

FileChange
include/json/jevent.h, include/xml/xevent.hJsonEvent and XmlEvent get code (static string, the stable kebab-case name) and span (bytes from at through the offending byte, 0 at the end of input), set on error events only
src/json/jnext.cjson_next() fills them from err_code / err_len; new json_next_end(), the event form of json_end(): the pull parser cannot tell the end of its input from a pause, so a caller that knows no more data comes calls it (until JSON_PULL_END) to get a trailing number or the unexpected-end error. Only strict flags report an unfinished document (JR_LEGACY never does)
src/json/jpump.cjr_feed() / jr_end() fill them from jr_error_name(err_code) / err_len
src/xml/xnext.c, src/xml/xpump.cxml_next() (mismatched-end-tag, span of </b> is 4) and xr_feed() / xr_end() (xr_error_name; unexpected-end span 0)
tests/c/event-model.cjson_error_info, xml_error_info: pull and push give the same code, span and position at chunk sizes 1, 2, 3 and whole; truncated JSON through json_next_end

With these a binding no longer reads err_code, err_len, tag_line of the parsers for an error; the remaining reads are the non-error ones (tag_line of events).

#4. Decisions taken while implementing (not in the first plan)

#DecisionReason
I1json_next / xml_next are added next to json_parse / xml_parse, not renamedthe bindings call the old ones; a rename would have broken the build outside include/ and src/
I2a walker is a JwalkSource / XwalkSource (iterator + capture), not jwalk_event(it, ctx, ev)the iterator must not move and the capture needs somewhere to live; the context is stored in the source
I3the XML processing instruction has no end event in xml.c (the ? is dropped, the frame stays open), so xml_next ends it at the first event that is not an attribute and replays that eventa quirk of the parser kept "verbatim" (EXCLAM == HYPHEN in xml.c); not changed because read() depends on it
I4an XE_ERROR from xml_next carries the stable code (mismatched-end-tag) in str, not the tag name that xml_pump sent beforethe error text of an event is its message, as in JsonEvent
I5XWALK_BALANCED closes unmatched elements at a marker for an outer one; it does not know void elementsknowing br is the consumer's job; <br>x</br> is the honest result of [br, 'x', /p]
I6max_depth counts levels as xml.write() does (walk depth / 2)byte-identical behaviour with the legacy cut-off
I7JsonEventSink.comment and .raw are the last membersjwrite_sink, jbuild_sink, tests/c/pump-roundtrip.c initialise the first eleven positionally
I8the builder's raw handler accepts a number, null, true, false and a quoted string without escapes; a string with a backslash is droppedJSON.rawJSON takes only primitives; decoding escapes belongs to the glue
I9sink members still take no position; at exists only on the eventunchanged from api-event-model.md Q4

#5. Known limits and open bugs of the new code

ItemDetail
JSON at for jr_feedtaken from jr_state_t.tok; checked only for the error case, not for every event type
xml_next atline and column of the last tag; none for text; no offsets (SourcePos.byte_offset / char_offset unset)

#P16 done

xml.write() is xwalk_source pumped into an XmlWriter (XW_PRETTY, indent 2) in quickjs-xml.c (xml_write_tree). xtreewrite.[ch] and xlayout.[ch] are deleted. Layout change: nested children are indented by 2 per level (tree and flat), no trailing newline, inline text keeps mixed content on one line, a maxDepth cut element is written <b />. tests/fixtures/xml-write-golden.json is regenerated.

#Slimming (after P16)

XMLParser.parse(), eventName/eventValue/hasValue, root, the on* callbacks, the builder option, PARSE_* and XMLNodeParser are gone, as are JsonParser.parse(), pos, token, state, NEED_DATA and NONE. next(), the iterator, pump(), depth, location and tolerant/comments remain. quickjs-xml.c 2211 to 1708 lines, quickjs-json.c 1837 to 1756. The consumers (lib/html.js, examples/html2md.js, qjs-lws examples/crawler/lib/html2md.js, utilities/jsonpp.js) use next(). A JSON event has raw for a number and the text as value for a comment. The old pull tests run on a Pull subclass in test-xml.js / test-json.js. Open: json_parse / xml_parse stay as engine functions under json_next / xml_next (P13 rest), tokenizer merge (P14), P15.

#Lifted out of quickjs-{json,xml}.c (no new files)

quickjs-json.c 1756 to 1412 lines, quickjs-xml.c 1708 to 1339. Moved into existing files:

  • jevent-js.c / xevent-js.c: json_read_value, xml_read_value, xml_write_value, xml_tree_list, js_xmlwrite_throw, js_jsonevent_throw, js_xmlevent_error.
  • jwalk.c: jwalk_stringify (the core of json.write()).
  • jopts.c / xopts.c: js_jsonwriter_ret, jwrite_js_value, jread_options_from_js (dialect and strict, shared by both JSON parsers), xml_html_self_closing_tags.
  • jsink.c / xsink.c: js_jsonsink_failed, js_xmlsink_failed.
  • jconnect.c / xconnect.c: JsonJsCallbacks / XmlJsCallbacks (the callback mode of the push parsers) and JsonJsTee / XmlJsTee (the JS-owning tee).

What stays is binding: classes, constructors, getters, finalizers, the push parsers' write/close error rules, module init.
