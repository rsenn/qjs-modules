#XML: how the implementation is split

> Status 2026-10-18 (implemented). The event model is in: every class is a source or sink over JsonEvent / XmlEvent, pump()/connect()/tee/JsonBuilder/XmlBuilder exist, parse() and XMLNodeParser are removed (next() and the iterator replace them), xml.write() is xwalk pumped into an XmlWriter (XW_PRETTY, indent 2), quickjs-json.c is 933 and quickjs-xml.c 967 lines. The layering described below is done except the lib/ glue for read/write, which stay native. > Running state and what is left: event-model-state.md. Text below that describes parse(), XMLNodeParser, > eventName/eventValue, PARSE_*, xtreewrite or xlayout is the plan or the history, those are gone.

quickjs-xml.c is meant to become what quickjs-json.c became: classes, argument parsing and error mapping, over engine-free pieces in include/ + src/. This document records where the code is now, which existing header could take over which part (every candidate was checked against the code), and what remains in the binding. Companions: api-compare-xml.md, api-interface-xml.md; the phase-by-phase plan and its status are in TODO.md Tier 20.

State 2026-10-17 (nothing committed): quickjs-xml.c is 2713 lines (HEAD had 3064). New pieces exist but have few callers yet.

#5.2 Throwing

One helper for every parser binding, in quickjs-location.[ch] (the module that owns Location):

/* builds a SyntaxError with own, non-enumerable loc (a Location clone), length and code.
 *
 *   const Location*  at      start of the offending token
 *   size_t           length  characters it spans (0 at end of input)
 *   const char*      code    stable kebab-case name
 *
 *   returns JSValue  the error object (refcount: a new reference), or JS_EXCEPTION */
JSValue js_syntax_error_new(JSContext*, const Location* at, size_t length, const char* code, const char* fmt, ...);
/* ... and throws it: returns JS_EXCEPTION with the SyntaxError pending. */
JSValue js_throw_syntax_error(JSContext*, const Location* at, size_t length, const char* code, const char* fmt, ...);

The object form is needed where nothing is thrown: JSONL.parseChunk().error, onError(err) / onParseError(err), parser.error, the members of an AggregateError, a promise rejection. The message is "<text> at <file>:<line>:<column>".

#5.4 Tests

tests/unittests/test-xml-errors.js: strict and lenient inputs (mismatched end tag, EOF in a tag, EOF in an element, duplicate attribute, unquoted value, undefined entity, two roots, text outside the root, control character, unterminated comment and CDATA, bad declaration) for read, XMLParser, XMLNodeParser, XMLPushParser, DOMParser; code, loc, length; chunk invariance for the push parser; the <parsererror> document for DOMParser; lenient repairs reach onParseError and never throw. Message texts of Bun's XML.parse are the oracle for which inputs are errors (api-compare-xml.md 3), not for the wording.

#6. State 2026-10-17

Done: read() on xbuilder; write() on xwalk + xlayout (src/xml/xtreewrite.c, tree and flat list; quickjs-xml.c is 2156 lines); XMLWriter on xwrite, decorated with the XmlEventSink methods by js_xmlsink_* (src/xml/xsink.c); XmlEventSink, pumps, XmlBuilder; error contract E0 to E2. Sections 2 and 3 above predate this; the open items are in TODO.md, "Remaining work: json and xml" (X1 to X8, B1 to B9).

#7. Plan 2026-10-18: engines in C, APIs in lib/

Decision (api-event-model.md): quickjs-xml.c holds engines, each a source or a sink, pull or push, over XmlEvent; read, write, DOMParser, XMLSerializer, XML.parse / XML.stringify and XMLNodeParser are compositions in lib/. What that does to the pieces:

PieceNowAfter

xread.c (push)xr_callback(type, xr_str_t* name, xr_str_t* value, user)XmlEventHandler(user, const XmlEvent*); kept as a tokenizer or deleted if xml.c over a push Reader measures as fast (Q5)
xpump.cxread_pump, xread_pump_finish, xml_pumpxevent_pump(xml_source(parser), sink); push pumps are one xr_read call with xevent_send as handler
xwalk.celement-tree walk through WalkInterfacealso xwalk_event(&src, &ev): the tag / attributes / children interpretation of xtreewrite.c lives here

Lines expected to leave quickjs-xml.c (2156 now, target about 1200 in TODO.md section 6, about 1000 with this plan): read / write (P9), the XMLNodeParser assembly and the four option-parsing copies (P7, P8), the replay serializer (P5), the callback glue of XMLPushParser (P3). Rules for every step: test-xml.js and test-xml-write-golden.js stay green apart from the changes listed in TODO.md; the read() differential against the pre-refactor parser stays at 0 on well-formed input; push output is the same at every chunk size.

#7.1 End state (plan 2026-10-18)

After the binding is lifted quickjs-xml.c is the list of classes (about 1000 lines): XMLParser, XMLPushParser, XmlBuilder, XmlWalker, XMLWriter, XMLTreeSerializer, tee. The rest goes to src/xml/: error shaping (xml_error_new, xml_throw_at, xml_pushparser_report, xml_nodeparser_record_error), the four copies of option parsing (xopts.c), event to JS value and JS-function handlers (xevent-js.c), handshake and js_xml_pump (xconnect.c), the serializer's read() (xserial-js.c), location_from_srcpos, reader_from_js_input. Deleted: js_xml_parse and XRFrame (read() becomes lib/xml.js), XMLNodeParser assembly, the replay serializer (XMLCappedBuf, xml_write_capped, xml_write_skip), the old entry points of xml.h / xread.h (private), xread.c (442 lines, if xml.c over a push Reader is as fast), and with X1 xtreewrite.[ch] and xlayout.[ch] (about 560 lines). Details, counts and gates: api-event-model.md 12; state: event-model-state.md.
