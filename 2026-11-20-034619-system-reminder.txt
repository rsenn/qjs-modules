  Please fix the AF_UNIX SockAddr bug in quickjs-sockets.c (qjs-modules); it is
  logged as sockaddr-unix-length in qjs-lws/BUGS.

  Symptoms, all seen with the installed qjsm 0.9 (757b576bf8ab-dirty):
  1. SockAddr(AF_UNIX).byteLength is 28, not sizeof(struct sockaddr_un) = 110,
     so only 26 bytes of sun_path are bound. Longer paths are truncated, and two
     different long paths can collide (EADDRINUSE).
  2. new SockAddr(AF_UNIX, path) leaves sun_path all zero, which is the shared
     Linux abstract-socket name. Every such socket binds to the same name, and a
     client connects to whichever process holds it.
  3. The likely cause is that the AF_UNIX case is missing or guarded by a
     HAVE_AF_UNIX / length check around quickjs-sockets.c:280. Please confirm in
     the source.

  Wanted:
  - SockAddr(AF_UNIX [, path]) allocates sizeof(struct sockaddr_un) and copies
    the path into sun_path (NUL-terminated).
  - A path that is too long throws a clear error.
  - Also support a leading NUL (abstract name) with an explicit length if that
    is easy.
  - The path getter and toString return the path again.

  Test: bind and connect on a path longer than 26 bytes (e.g.
  /run/user/1000/ollama-repl/4039043.sock), two different long paths bound at
  once, and a round trip of the path through the getter.

● The AF_UNIX SockAddr bug is fixed and the new qjsm is installed in /usr/local.
  new SockAddr(AF_UNIX).byteLength is now 110, and I messaged the ollama-repl
  session to say so. test-sockets.js passes (32 tests); I did not run the rest
  of ctest.

  - Cause: HAVE_AF_UNIX in quickjs-sockets.c was only defined when HAVE_AFUNIX_H
    was set, which is Windows only. On Linux, sockaddr_un was not in the
    SockAddr union, so the length fell back to 28 bytes. The AF_UNIX path code
    for the constructor, getter and setter was also compiled out.
  - Fix: it is now defined for every non-Windows build, and for MSYS and Cygwin.
  - Behaviour:
    - new SockAddr(AF_UNIX, path) copies the path into sun_path, and the getter
      and toString return it again.
    - A path of 108 bytes or more throws RangeError, from the constructor and
      from the path setter.
    - If the constructor throws, the error now propagates instead of being
      ignored.
  - Test: the new SockAddr AF_UNIX long path test in
    tests/unittests/test-sockets.js binds two different paths longer than 26
    bytes at once, connects over one, and checks the path round trip.
  - Bookkeeping: I removed the sockaddr-unix-length entry from qjs-lws/BUGS.
    qjs-modules has no ChangeLog file, so I added nothing there.

  I did not add abstract-name support (a leading NUL with an explicit length).
  SockAddr has no length field, so bind and connect always use 110 bytes, and an
  abstract name would not match other programs. Say if you want a length field
  added.
